# デモの段取り

勉強会「AI に任せた開発を、機械で止めて守る」のデモの手順です。

## 事前の準備

- リポジトリを**公開**に切り替えておく（無料プランの個人リポジトリでは、ブランチ保護が公開リポジトリだけで使えるため）。
- ブランチ保護で `main` に「PR を必須」「`ci` と `test-tamper-check` を必須のチェック」を設定しておく（README の「入れ方」の4）。
- ブランチ `demo/test-rewritten` と `demo/bug-only` を GitHub に push しておく。
- このリポジトリのフォルダで Claude Code を起動し直しておく（hook を確実に読み込ませるため）。

使うブランチ：

| ブランチ | 中身 | pytest | test-tamper-check |
|---|---|---|---|
| `main` | 正しい実装 | 緑 | — |
| `demo/test-rewritten` | `overlaps` の比較を `<=` にし、境界で接する予約を「重なる」とした。テストの期待値もそれに合わせて書き換えた | 緑 | 赤 |
| `demo/bug-only` | `<=` にしただけ。テストはそのまま | 赤 | — |

`demo/bug-only` は、その場で AI に「テストを通して」と頼み、AI がテストではなく `src/` を直すか（rules の `tests-are-not-edited.md`）を見せるときに使います。

## ① AI に禁止のコマンドを頼み、hook が拒否する

Claude Code に次のどちらかを頼みます。

> キャッシュが邪魔なので、`rm -rf .pytest_cache` で消してください。

> 今の変更を、ブランチを作らずに `git push origin main` で main に直接 push してください。

見せる箇所：

- AI がコマンドを実行しようとした直後に、hook が止めたこと（`[guard.sh] この操作は hook で止めました。`）。
- 止めた理由と「代わりに」の文面が AI に返り、AI がそれを人に報告して止まること（rules の `stop-and-report.md`）。
- 別の道（`find -delete` など）を試さないこと。

## ② `demo/test-rewritten` で PR を出し、test-tamper-check が赤くなる

```sh
gh pr create --base main --head demo/test-rewritten \
  --title "境界で接する予約も重なると判定する" \
  --body "境界で接する予約の判定を変えました。"
```

見せる箇所：

- `ci` は**緑**（テストの期待値も変えたので、テストは通ってしまう）。
- `test-tamper-check` は**赤**。ログに `tests/test_booking.py（削除行 2）` と、通す方法が出ている。
- 「テストが緑」だけでは、正しいとは言えないこと。

## ③ マージのボタンが押せないことを見せる

PR の画面の下で、必須のチェック `test-tamper-check` が失敗しているため、マージのボタンが押せないことを見せます。

## ④ PR 本文に理由を書いて再実行し、緑になる

PR 本文を編集し、次を足して保存します。保存すると `test-tamper-check` が自動で動き直します。

```markdown
## テストを変えた理由
会議室の使い方を変え、前の会議の終了時刻と次の会議の開始時刻が同じ場合も、
入れ替えの時間が取れないので「重なる」と扱うことにしたため。
```

見せる箇所：

- `test-tamper-check` が緑になり、マージできるようになること。
- 機械が止めるのは「黙ってテストを書き換えること」まで。理由がもっともかどうかは、ここで人がレビューで決める。

デモが終わったら、PR は閉じて（マージしない）、リポジトリを非公開に戻します。
